# Phase 02.5 Plan 01: Web Server Safety Summary

**`/api/generate-cli` now runs `subprocess.run(tokens, shell=False)` behind an argv-token allow-list, and returns only the images that request created**

## Accomplishments

- Removed the network-reachable shell injection: `subprocess.run(command, shell=True)` behind a `startswith` guard that `imagai; <cmd>` bypassed is gone, replaced by `subprocess.run(tokens, shell=False)` where `tokens = shlex.split(command)` (D-01).
- The allow-list is enforced on the token sequence, not the raw string — `ALLOWED_COMMAND_PREFIXES` (three prefixes) + `ALLOWED_SUBCOMMANDS` (`generate`, `list-engines`, the CLI's entire surface) + `_allowed_argv()` predicate. `imagai generate; touch /tmp/pwned` tokenizes to the subcommand token `generate;` and is rejected before any subprocess exists.
- Replaced the 300-second mtime window, which returned every concurrent caller's images on every call, with `_png_snapshot()` before/after set-diff (D-04). A pre-existing file in the output directory is now provably absent from the response.

## Decisions Made

- No metacharacter blocklist over the tokens after the subcommand. `imagai generate -p "a cat; rm -rf /"` remains an allowed command: with `shell=False` that token reaches the binary as one literal argv element and no shell ever interprets it. Filtering it would reintroduce the exact mechanism D-01 exists to delete.
- `shlex.split` failures return 400 with a populated error body. CONTEXT left the 400-vs-500 choice to agent discretion; Phase 2 D-04 requires only that the body be populated and the exception never escape.
- Concurrent-request race left as accepted debt, with the upgrade path (`threading.Lock` around snapshot → run → diff) named in a `ponytail:` comment rather than built.
