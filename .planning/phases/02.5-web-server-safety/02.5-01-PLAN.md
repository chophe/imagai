<objective>
Rewrite `/api/generate-cli` so it executes an allow-listed argv with `shell=False`, and return only the images that request created.

Purpose: `web_server.py:248-255` passes a caller-supplied string to `subprocess.run(..., shell=True)` behind a `startswith` guard that `imagai; <cmd>` bypasses — a network-reachable RCE by default. D-01 removes the shell entirely rather than filtering for it, because a blocklist over a shell string is the exact mechanism that produced the bypass. D-04 stops the endpoint from returning other requests' images, which the current 300-second mtime window does on every call.

Output: `_allowed_argv` token gate, argv-only `subprocess.run`, before/after directory diff, and `tests/test_web_server.py` proving both the exploit and the happy path.
</objective>

## Phase Goal

**As a** developer running the imagai dev server, **I want to** `POST /api/generate-cli` and have the request executed as an argument vector against an allow-listed command, **so that** no string I send can ever reach a shell interpreter.

## Acceptance Criteria

- `{"command": "imagai; touch /tmp/pwned"}` → 400, `subprocess.run` never called, `/tmp/pwned` does not exist (ROADMAP criterion 1)
- `subprocess.run` called with a `list` first positional arg and `shell=False`; `rg -n "shell=True" src/` returns nothing (criterion 2)
- `imagai generate; touch /tmp/pwned` → 400 despite `imagai` being an allowed first token (criterion 3)
- A pre-existing file in the output directory is absent from `generated_images` (criterion 8)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request → argv | The `command` field of `POST /api/generate-cli` is caller-controlled and, before this plan, was handed verbatim to a shell |
| Web page → dev server | Any page in the developer's browser can issue a cross-origin POST to `127.0.0.1:5000` |
| Request → output directory | `generated_images` is built by scanning `settings.output_dir`, a directory shared by every concurrent caller |
