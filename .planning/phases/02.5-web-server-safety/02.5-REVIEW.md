## Summary

Reviewed the diff `69cf917..HEAD` (12 commits) closing the network-reachable RCE in
`/api/generate-cli`: the `shell=True` + `startswith` call replaced by
`subprocess.run(shlex.split(command), shell=False)` behind the `_allowed_argv` token gate,
the mtime-window image scan replaced by a before/after set-diff, `main()` defaulting to
`127.0.0.1`/`debug=False` and hoisted above the `__main__` guard, `flask-cors` removed, and
the doc claims corrected. Full suite: **34 passed, 1 deselected** (`uv run pytest -k "not llm"`).

**Security verdict: the allow-list gate cannot be defeated.** I probed it with 26 payloads
(quote smuggling, `;`/`&&`/backtick/`$()`/`$IFS`, newline, unicode, empty tokens, `./`-prefixed
argv[0], flag-interleaved prefixes, NUL bytes, unbalanced quotes). Every shell-metacharacter
payload is either rejected at the token gate (metacharacters become literal argv tokens for
`imagai`, e.g. `imagai generate && curl evil` → `['imagai','generate','&&','curl','evil']`)
or fails closed (`./imagai`, `IMAGAI`, `""`-prefix, `imagai" "generate`, `uv run --quiet imagai`).
There is no shell in the path to reinterpret any token. `rg -n "shell=True" src/ tests/
pyproject.toml uv.lock docs/ README.md` prints nothing (exit 1), and `web_server.py:302` is the
only process-spawn site in the repo (`tests/test_toolchain.py:35` runs an argv list).

**Set-diff: not defeated serially, bled by concurrency.** No serial attack returns a
pre-existing file — no TOCTOU (snapshot is inside the gate, after the 400 checks), no
extension/case collision (`glob` is case-sensitive; `_contained_path` at the save layer rejects
`-o ../..//abs`), no seeded-name trick (an overwritten name stays in `before` and is excluded).
The one demonstrated defeat is a concurrent request seeding a file between snapshot and diff —
see WR-02.

Scope boundary honored: the duplicated request-object build in `generate_image()`
(`web_server.py:127-172`) and the unbounded `except Exception` at that boundary are Phase 3/4
work and are not filed here.

## Warning Issues

### WR-01: `command` field is not type-checked — non-string JSON returns 500 + internal error text

**File:** `src/imagai/web_server.py:274-283`
**Issue:** The handler checks `"command" not in data` but not its type. JSON permits any type
for the value, so `{"command": 123}` / `{"command": ["imagai","generate"]}` /
`{"command": {"a":1}}` reach `shlex.split`, which raises `AttributeError` (not `ValueError`),
fall through the inner `except ValueError`, and hit the outer `except Exception` → HTTP **500**
with the raw internal message leaked to the caller. Verified against the test client:

```
{"command": ["imagai","generate"]} -> 500 {'error': "'list' object has no attribute 'read'", 'success': False}
```

`None` happens to return 400 (shlex raises `ValueError` for it), so the contract is
type-dependent. Trust-boundary input validation (ASVS L1) expects a 400 for a malformed
field. `subprocess.run` was never called in any of these probes.
**Fix:** `if not isinstance(command, str): return jsonify({"success": False, "error": "Command must be a string"}), 400`
before `shlex.split`.

### WR-02: set-diff returns a concurrent request's file (SEC-08 residual, acknowledged)

**File:** `src/imagai/web_server.py:300-325` (ponytail comment at `:322-324`)
**Issue:** `before = _png_snapshot()` → run → `_png_snapshot() - before` is not serialized,
and `main()` defaults to `threaded=True`. I demonstrated the race: with request A's subprocess
in flight, a second thread writing `from_request_B.png` into the output dir causes **A's
response to contain B's image**. Not a pre-existing-file leak (the serial case is correct) and
not attacker-chosen content — but it is exactly the cross-request disclosure SEC-08 targets,
surviving under `threaded=True`. The `ponytail:` comment names the ceiling and upgrade path
(`threading.Lock` around snapshot→run→diff); the review confirms the ceiling is real, not
theoretical.
**Fix:** the acknowledged `threading.Lock`, or accept and track it as a known limit of the
dev-server posture.

## Info Issues

### IN-01: Overwrite-in-place returns an empty `generated_images` list

**File:** `src/imagai/web_server.py:325`
**Issue:** If the subprocess overwrites an existing name (explicit `imagai generate -o old.png`,
or a repeated deterministic auto name), the path is in `before` and excluded, so a successful
request reports `generated_images: []` (verified). The old mtime window returned these. Rare in
practice — default filenames are timestamped — but a re-run with `-o` silently returns nothing.

### IN-02: `tests/test_cli.py` still holds two `assert True` stubs

**File:** `tests/test_cli.py:1-6`
**Issue:** `test_app_version` and `test_generate_help` are unchanged stubs, while the real
coverage (`test_generate_help_exits_0`, `test_api_generate_contract_unchanged`) was filed in
`tests/test_web_server.py:295-314`. Behavior is covered; the stubs are misleading and invite a
future reader to trust them.

### IN-03: `render_template_string` imported but unused

**File:** `src/imagai/web_server.py:19`
**Issue:** Pre-existing unused import (the line was edited by this phase to drop
`flask_cors`). Lint noise only.

### IN-04: Unbounded argument surface after the subcommand — cost/quota abuse, not compromise

**File:** `src/imagai/web_server.py:249`
**Issue:** The gate constrains prefix + subcommand but not the subcommand's arguments:
`imagai generate -n 100` spends API quota, `imagai list-engines --all` triggers outbound fetches
to every configured engine. The endpoint is unauthenticated, so this is free compute/cost for
any caller. Imagai's filesystem-touching option (`-o`) is contained at the save layer
(`utils.py:182,223` — parent must equal the output dir), and `list-engines` masks API keys,
so nothing beyond cost is reachable. Noted for the auth/quota work, not a defect in this phase's
diff.
