# Phase 2.5: Web Server Safety - Context

**Gathered:** 2026-10-07
**Status:** Ready for planning

<domain>
## Phase Boundary

The dev server starts safely from source, binds only to localhost, and cannot execute a
caller-supplied shell string. Concretely: `/api/generate-cli` runs with `shell=False` against an
allow-listed argv, the API is not reachable cross-origin from arbitrary web pages, and the endpoint
returns only the images that request created.

Requirements: SEC-03, SEC-05, SEC-06, plus SEC-07 and SEC-08 added by this discussion.

Explicitly out of scope: HTTP request-shape validation (Phase 3, SEC-04), error propagation beyond
the existing contract (Phase 4), config cleanup (Phase 5), provider registry (Phase 6). Adding
authentication is explicitly out of scope — this phase's job is to make "localhost-only" true again
so that premise holds.

</domain>

<decisions>
## Implementation Decisions

### Command execution
- **D-01:** Keep `/api/generate-cli`, but run it argv-only. Parse the incoming `command` string with
  `shlex.split` and invoke `subprocess.run(tokens, shell=False, ...)`. The shell's parsing of `;`,
  `|`, `&&`, and backticks is removed entirely rather than filtered for — a blocklist over a shell
  string is exactly the mechanism that produced the current bypass.
  — **Reversibility:** reversible.
- **D-02:** The allow-list is enforced on the *token sequence*: an allowed invocation prefix
  (`imagai`, `uv run imagai`, or `python -m imagai`) followed by exactly one of the two subcommands
  the CLI actually exposes (`generate`, `list-engines`). Everything after the subcommand is data
  passed through as argv. A command whose prefix or subcommand does not match is rejected before any
  subprocess is created.
  — **Reversibility:** costly — adding a CLI subcommand later requires updating this list, or the
  endpoint silently rejects a legitimate command.
  - Note: `cli.py` currently exposes exactly two commands (`generate`, `list-engines`) plus a
    global `--version` callback. This is why a tight allow-list is practical.

### Cross-origin reachability
- **D-03:** Remove `CORS(app)` and drop the `flask-cors` dependency. `GET /` serves
  `web_interface.html` from the same origin (`web_server.py:39-49`), and that UI consumes only
  `/api/generate` and `/api/engines` — so the bundled client is same-origin and never needed CORS.
  Wide-open CORS existed only to admit *other* origins, which is precisely the drive-by path: any web
  page in the same browser could POST to the dev server.
  — **Reversibility:** reversible — reintroducing CORS is trivial if a separately-hosted UI appears.
  - Touches `pyproject.toml:17` and requires `uv lock` regeneration. Also corrects stale claims in
    `docs/architecture.md:6,36` and `docs/dependencies.md:21`.

### Cross-request image leakage
- **D-04:** Stop returning other requests' images. Snapshot the output directory before running the
  command and diff after, returning only newly-created files. One `generate` run may create N
  numbered variants, and the diff captures the whole batch naturally.
  — **Reversibility:** reversible.
  - **Accepted debt:** the before/after diff still races under *truly* concurrent requests — two
    simultaneous calls can each diff and observe the other's files. Fully closing it requires a lock
    (or a run-id) around the run, which serializes a threaded server. Chosen trade: correct in the
    common case, documented residual in the concurrent case. Upgrade path: `threading.Lock` around
    snapshot→run→diff, if a concurrent-use report ever justifies serializing the endpoint.

### Server defaults (locked at roadmap creation)
- **D-05:** `main()` is defined above the `if __name__ == "__main__":` guard, so
  `python src/imagai/web_server.py` starts without `NameError` (SEC-03).
- **D-06:** `main()` defaults to `host="127.0.0.1"` and `debug=False`, so a bare `imagai-web` binds
  loopback only with no interactive debugger (SEC-06). Both remain overridable by explicit argument.

### the agent's Discretion
- Whether the allow-list is expressed as a tuple of (prefix-tuple, subcommand-tuple) pairs or as a
  small helper predicate; either satisfies D-02.
- Whether `shlex.split` failures (unbalanced quotes) return 400 or fall through to the generic error
  path — but the response must be a populated error body, never a raised exception (carrying forward
  Phase 2's D-04).
- Exact wording of rejection messages.
- Whether the existing 300s subprocess timeout is retained as-is.
- Test file layout and naming; `pytest` via `uv run pytest` is the established runner, and tests must
  **not** invoke a real shell (`codebase/TESTING.md:554`) — mock `subprocess.run`.
- Order of doc corrections (`docs/architecture.md`, `docs/dependencies.md`) relative to the code
  change.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `shlex` from the stdlib — tokenizes the command string without invoking a shell.
- `cli.py`'s Typer app already defines the exact subcommand set the allow-list needs; the allow-list
  and the CLI cannot drift silently because both are small and adjacent.
- Phase 2's `tests/test_containment.py` — the template for proving an exploit with a test and then
  proving the happy path still works (13 tests, no framework beyond pytest).

### Established Patterns
- Errors surface as a populated JSON body with a 4xx status, never a raised exception (Phase 2 D-04).
- The web layer is the only consumer of `flask`/`werkzeug`; neither the CLI nor the core imports
  them (`codebase/STACK.md:75`), so stack-level changes here do not ripple.
- `pytest` via `uv run pytest`, bare functions, no classes or fixtures.

### Integration Points
- `UPLOAD_FOLDER` (`web_server.py:33`) is `settings.output_dir` after Phase 2 — the before/after
  diff snapshots this exact directory.
- `pyproject.toml` → `uv.lock` must stay consistent; dropping a dependency without regenerating the
  lockfile leaves Phase 1's ENV-01/ENV-02 criteria broken.

</code_context>

<specifics>
## Specific Ideas

Verification is expected to be test-shaped, mirroring Phase 2's approach:

- `{"command": "imagai; touch /tmp/pwned"}` → rejected, no subprocess created, `/tmp/pwned` absent.
- No call site in the repo passes `shell=True` — provable by grep.
- The allow-list rejects a disallowed subcommand before any subprocess exists.
- `main()` defaults asserted to `127.0.0.1` / `False`.
- A test drives `generate-cli` twice with a pre-existing image in the output directory and asserts
  the first response does not contain the pre-existing file.

**Tests must mock `subprocess.run`** — no real shell execution in the suite.

**Dependency removal is a phase deliverable**, not a follow-up: `pyproject.toml`, `uv.lock`, and the
three stale doc claims move together, or Phase 1's clean-install criteria regress.

</specifics>
