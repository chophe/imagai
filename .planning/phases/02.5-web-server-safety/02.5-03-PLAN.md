**Do not hand-edit `uv.lock`.** Five lines sit in that package's footprint and all five self-resolve when the manifest drops the requirement. Three carry the hyphenated `flask-cors`: the `name = "flask-cors"` package header (`:175`), the `{ name = "flask-cors" }` entry under the `imagai` requires-dist (`:280`), and the `{ name = "flask-cors", specifier = ">=3.0.10" }` metadata entry (`:304`). Two more carry the **underscored** `flask_cors` inside that same block's distribution URLs — the `sdist` line (`:183`) and the `wheels` entry (`:185`). Editing any of them by hand produces a lockfile that `uv` will reject or silently re-resolve.

Because those two URL lines spell it with an underscore, the gate below greps `flask[-_]cors`, not the bare package name — a hyphen-only grep would pass while those URLs survived.

Prove the chain holds — `pyproject.toml` → `uv.lock` → the installed environment all agree — with two gates:

- `uv lock --check` exits 0, meaning the lockfile is in sync with the manifest. This is a pure check; it reports an out-of-date lockfile without rewriting it, so it is safe to re-run.
- `uv run python -c "from imagai.web_server import app; print('IMPORTS OK')"` prints `IMPORTS OK`, meaning a resolved environment still satisfies every import `web_server.py` makes. This is the direct check that the removal did not take `flask` or `werkzeug` with it.

Finally `rg -n "flask[-_]cors" pyproject.toml uv.lock` must print nothing.

Note that the installed `flask-cors` version was 6.0.5 while `docs/dependencies.md:21` claimed 6.0.1 — that row is deleted in Task 2, so the discrepancy never has to be reconciled.
