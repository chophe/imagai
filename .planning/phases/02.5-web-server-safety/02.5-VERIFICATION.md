### Observations for later phases (documented, not Phase 2.5 gaps)

1. **`&&`/`|`/`$()`/backtick/newline payloads pass the token gate as literal argv tokens.** This is
   safe — no shell exists in the path (proven with a real subprocess run) — and is the documented
   D-01/D-02 design plus review-probed behavior, not a hole. Worth knowing that ROADMAP criterion 3
   read universally ("rejected when later tokens contain shell metacharacters") is satisfied in its
   demonstrated `;`-adjacent form; the space-separated forms are neutralized by design instead of
   rejection. If the team later wants literal rejection of any metacharacter token, that is a
   tightening, not a fix.
2. **Cross-endpoint residual (Phase 3's, filed by the review fixer).** `/api/generate` writes into
   the same `settings.output_dir` and takes no lock, so its file can land in a concurrent
   `/api/generate-cli` response. Reproduced by the fixer (`02.5-REVIEW-FIX.md`, Observation 1);
   the generate-cli ↔ generate-cli half (WR-02) is fixed and re-verified above. Serializing both
   write paths belongs to the Phase 3 rewrite of `generate_image()`.
3. IN-01 (overwrite-in-place returns empty `generated_images` — the SEC-08-safe behavior), IN-02
   (`tests/test_cli.py` `assert True` stubs, QUAL-01), IN-04 (unbounded post-subcommand argument
   surface — cost/quota, not compromise) are tracked in `02.5-REVIEW-FIX.md` for later phases.
4. All 13 plan-declared threats in `02.5-SECURITY.md` were independently spot-verified here
   (T-025-01…08, 11, 12); commits `890c496`, `657d0d3`, `303f318`, `cee937c` and the rest of the
   phase's history exist on `gsd/phase-01-runnable-toolchain`.
