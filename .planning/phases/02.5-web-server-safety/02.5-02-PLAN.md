The script-mode proof is the task's `<verify>` command, not a pytest test. - Stubbing on the class (not on an app instance) is what makes `runpy` correct here. `run_path` builds a *second* `app` object, so a `patch.object(web_server.app, "run")` prepared beforehand would not intercept the call and would bind a real port. `Flask.run = <lambda>` on the class intercepts whichever instance `main()` ends up calling.

Assert the banner text in the captured stdout, so the criterion's "prints its startup banner" half is proven by the same command.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Process start → module execution | Running the file as a script executes the `__main__` guard at module scope, before any function defined later in the file |
| Network → listening socket | `app.run(host=...)` decides which interfaces accept connections; `debug=True` attaches a Werkzeug debugger to that socket |
| Browser page → dev server | A page on any origin issues a preflight/POST at `127.0.0.1:5000`; the CORS headers on the response decide whether the browser lets the attacker read the reply |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-025-05 | Denial of Service / Elevation of Privilege | `main(debug=True)` Werkzeug debugger on the bound interface | high | mitigate | Task 2 flips the `debug` default to `False` and Task 1 pins it with a signature test. Paired with Task 2's `host` default, the debugger is no longer reachable from off-box. Explicit `debug=True` remains available for a deliberate local session. |
| T-025-07 | Elevation of Privilege | `main(host="0.0.0.0")` default bind | high | mitigate | Task 2 changes the `host` default to `127.0.0.1`, so a bare `imagai-web` is loopback-only. This is what restores the PROJECT.md premise that made auth out-of-scope defensible. |
