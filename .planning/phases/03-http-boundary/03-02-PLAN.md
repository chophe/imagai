<test_conventions>
Reuse the patterns already proven in this file (see the Phase 2.5 summaries):
- Mocking provider dispatch: `patch.object(web_server, "generate_image_core", <async callable>)` — the name is bound at module scope (`from imagai.core import generate_image_core`), so patch the module attribute. The callable must be awaitable-returning (an `async def` recorder or `AsyncMock`) because the endpoint does `asyncio.run(generate_image_core(req))`. To assert "never reached", check the mock's call count is zero.
- File-touching tests: wrap in `tempfile.TemporaryDirectory()` and `patch.object(web_server, "UPLOAD_FOLDER", Path(tmpdir))` plus `patch.object(settings, "output_dir", str(tmpdir))`, exactly as `test_generate_cli_returns_only_new_files` does.
- Base64 sample: build payloads against the module's `B64` constant.
- Use the shared `client` fixture added by Plan 03-01 for ALL new tests (do not reintroduce per-test `app.test_client()` duplication).
- Engine guard: the endpoint resolves `engine = data.get("engine") or settings.default_engine` and rejects unknown engines BEFORE the payload-schema gate. New rejection payloads must carry a valid `prompt` and a valid engine — pass `engine=settings.default_engine` (fall back to `next(iter(settings.engines))` if the default is unset). Assert this precondition once so a config-variance can't masquerade as a pass.
- Every new command in the suite stays offline: dispatch is mocked and the run always uses the MANDATORY `-k "not llm"` filter.
</test_conventions>
