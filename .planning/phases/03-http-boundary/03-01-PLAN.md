Pydantic default-vs-None ground truth (verified on pydantic 2.13.5):
- Omitting a field applies the model default (`n`→1, `size`→"1024x1024").
- Explicitly passing `None` for an `Optional` field sets it to `None`, NOT the default. Therefore `n=data.get("n")` (None when absent) would silently break the happy path.
- Resolution — pass RAW values for the keys actually present and OMIT absent keys so pydantic owns its own defaults: build `validated = {k: data[k] for k in ("size","n","quality","style") if k in data}` and splat it; pass raw `"abc"` / `"10x10"` and pydantic raises `ValidationError` (a 400), while `n="5"` lax-coerces to 5.
- The ONE web default that differs from the model is `response_format` (web `"b64_json"` vs model `"url"`). Preserve the web default to keep the happy path identical to this phase's start; its reconciliation is Phase 6 work and must NOT change here (success criterion 4).
